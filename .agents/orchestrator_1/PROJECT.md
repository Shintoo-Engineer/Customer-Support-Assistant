# Project: Task 4 Combined Phase 7 & 8 (Intent & Sentiment Analysis Agent)

## Architecture
The system connects Task 3 (Customer Simulator) with Task 4 (Intent & Sentiment Analysis Agent) in a continuous multi-turn dialogue loop.
- **Task 3 Engine (Protected Baseline)**: 6 personas (`persona_service.py`), 5 scenarios (`scenario_service.py`), emotional state machine (`simulator_state.py`), REST endpoints (`POST /simulator/start`, `POST /simulator/message`, `GET /simulator/{session_id}/history`).
- **Task 4 Core (Protected Baseline)**: Pydantic schemas (`app/schemas/analysis.py`), Analysis Service (`app/services/analysis_service.py`), Decision Support Service (`app/services/decision_support_service.py`), REST endpoints (`app/api/analysis.py`).
- **Data Flow**:
  1. Customer message generated by Task 3 Simulator (or submitted directly to `/analysis/analyze`).
  2. Task 4 `analyze_customer_message` extracts intent, emotion, sentiment, frustration, satisfaction trend, escalation risk, confidence.
  3. Snapshot persisted non-invasively to `messages` table with `message_type='System'`, `sender_type='AI'`.
  4. Decision support derived deterministically via `generate_decision_support` without secondary classifiers.
  5. Dialogue history in `/simulator/{session_id}/history` returns user/agent messages cleanly filtering out system analysis records.
  6. Analysis history in `/analysis/{session_id}/history` parses and returns chronological `TurnAnalysis` snapshots.
- **Resilience**: Dual-tier Gemini LLM (`gemini-3.5-flash` -> `gemini-3.5-flash-lite`) with automatic deterministic rule-based fallback ensuring schema validity under network failure, invalid credentials, or rate limits. Real Gemini status reported honestly.
- **Failure Isolation**: Simulation continues uninterrupted even if analysis throws an exception (`try...except` guard in `api/simulator.py`).

## Interface Contracts
### Task 3 Simulator <-> Task 4 Analysis Service
- Function: `analyze_customer_message(session_id: str, customer_message: str, db: Session) -> AnalysisResult`
- Persistence: `messages` table, `message_type="System"`, `sender_type="AI"`, `message_text=json.dumps(analysis.model_dump())`
- Filter contract:
  - Simulator history query: `Message.message_type != "System"`
  - Analysis history query: `Message.message_type == "System"`
- Failure isolation: In `app/api/simulator.py`, analysis execution is wrapped in `try...except Exception as e`, logging a warning and letting simulator continue normally.

### Task 4 Decision Support
- Function: `generate_decision_support(analysis_result: AnalysisResult, history: Optional[List[TurnAnalysis]] = None) -> DecisionSupportResult`
- Deterministic logic: Strictly rules-based; no external LLM or secondary classifier.
